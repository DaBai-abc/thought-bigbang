# S2 方向发散

## 目标

给出 3 到 5 个**真正不同**的方向，让用户看到自己这条原料的可能范围。这一步给的是选择权，不是答案。

## 硬要求：方向必须互斥

最常见的失败是给五个方向，实际是同一个意思换了五种说法。用户挑完发现做出来都一样。

**差异化检验（必须执行）：** 把任意两个方向放在一起，问一句——删掉其中一个，会丢失什么信息？如果答不上来，这两个就是重复的，删掉一个，重新想。

## 角度类型库

至少覆盖三种不同类型。全都落在同一类型里，说明发散不充分。

| 类型 | 结构 | 适用起点 |
|---|---|---|
| 反常识 | 多数人以为 A，其实是 B | 信息差、专业型 |
| 私密自述 | 我经历了一件平时不说的事 | 痛点、对话 |
| 工具实用 | 三步解决某个具体麻烦 | 痛点、成熟方案 |
| 冲突对立 | 两种做法正面撞，各有代价 | 成熟方案、观点型 |
| 时间线 | 三年前我以为 X，现在知道 Y | 自述、成长型 |
| 拆解 | 把一件事拆开，让你看见内部 | 信息差、专业型 |
| 对照实验 | 我做了 A 和 B，结果差在哪 | 实证型、工具型 |

## 每个方向的必填项

```markdown
### 方向 N：<一句标题，直接说主张，不要"关于XX的思考">

**主张**：<一句话，能被反对的那种。不能被反对的主张不是主张。>

**第一句话 / 第一个画面**：<具体写出来，让人一看就知道这是什么调性>

**为什么这个角度成立**：<人群的哪个焦虑被击中了>

**形态适配**：<视频 / 图文 / 海报 / 播客，标注最合适的那个>

**需要什么**：<这个方向成立所必需的条件，尤其是不可能临时补的>

**风险**：<可能翻车的具体点，不要写"可能不够吸引人"这种废话>
```

## 判断标准

- **主张要能被反对。** "要多陪家人"没人会反对，也就没人会记住。"劝你别把父母接到城里住"才有人想吵。
- **第一句话要具体。** 写"聊聊职场焦虑"是空的，写"我被优化那天，HR 说了句让我记了三年的话"才是实的。
- **风险要具体。** "数据可能不准"是具体的，"可能效果不好"是废话。

## 推荐的方式

给完五个方向后，可以标出 1 到 2 个**在当前资源下最可能做成**的，说明理由，但必须同时说明另外几个为什么没被推荐——用户可能恰恰想挑战那个难的。

推荐理由只能基于两件事：和 S1 人群的匹配度、和 S3 资源的匹配度。不要基于"我觉得这个更有意思"。

## 产出格式

写 `03-angles.md`，依次列出各方向，末尾加一节：

```markdown
## 我的推荐
优先：方向 <N>，因为 <和人群匹配 / 资源够用>
次选：方向 <N>，因为 <>
不推荐但值得知道：方向 <N>，因为 <需要 XX 条件，当前不具备>
```

## 收尾

闸门问题通常只有一个：这几个方向里，哪个让你眼睛亮了一下。注意不要问"你选哪个"——要问"哪个让你有反应"，因为很多人此刻还选不出来，但有反应是能感知的。

## 做好的标准

用户看完会纠结。如果用户一眼就选定了，要么方向做得太好，要么太保守——更可能是后者。五个方向里至少应该有一个让他觉得"这个我有点不敢做"。

## 落链与面板

每个方向为什么给，写进 `决策链.md`，重点写清**它和其他方向的区别在哪**——那句区别就是互斥性的证据。写不出区别的，说明这个方向是凑数的。

写完 `03-angles.md` 后，把五个方向同步进 `panel/data.json` 的 `angles` 字段，渲染面板（`scripts/render_panel.py`），让用户在方向墙上直接勾选和淘汰。面板上选完导出数据，覆盖回 `panel/data.json`，再据此更新 `03-angles.md` 和 `00-state.md`。

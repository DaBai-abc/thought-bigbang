# 决策链

## 这份文件是干什么的

不是记录"AI 想了什么"。模型内部的推理过程拿不到，事后复述的"思考过程"都是编的，对创作者没有价值。

它记录的是**每一个判断的依据，以及什么情况下这个判断会失效**。目的是让用户能逐条反驳——看到依据不成立，直接推翻，不用整段重来。

判断一条决策链合不合格，只有一个标准：**用户看完能不能说出"你这条依据不成立，因为……"。** 说不出来，说明依据写空了。

## 存放

项目目录下 `决策链.md`，贯穿全程，只追加不删改。决策被推翻时追加一条新条目，注明取代了哪一条，不要直接改写历史。

## 单条格式

```markdown
## D-<序号> · <阶段>

**决策**：<一句话，具体到能被检验>
**依据**：
- <来源：用户原话第几句 / S<n> 的哪条结论 / 哪个具体事实>
- <尽量给可核验的东西：数字、原话、场景>
**反证条件**：如果 <什么情况成立>，这条判断失效，需要改成 <什么>
**影响范围**：<这条错了会连锁影响哪些后续决策>
**时间**：<YYYY-MM-DD HH:MM>
```

## 各阶段该记什么

| 阶段 | 必须落链的决策 | 依据来源 |
|---|---|---|
| S0 | 起点类型判定 | 用户原话里的哪些词指向这一类型 |
| S1 | 人群定位、要的动作、可信度路径 | 用户原话、已知的受众反馈 |
| S2 | 每个方向为什么值得给（尤其要标出为什么互斥） | S1 的哪个焦虑被击中 |
| S3 | 八项评分中的每一项、选定的方向、裁剪决定 | 用户自述的条件、过往行为 |
| S4 | 钩子用哪种、主线走故事线还是信息线 | 起点类型、人群状态 |
| S5 | 素材走检索/生成/拍摄的分配依据 | 版权、成本、可控性 |
| S6 | 平台选择、发布时间 | 人群活跃时段、平台特性 |

S0 和 S3 的决策链最关键。前者错了全歪，后者错了会烂尾。

## 不合格的依据长什么样

出现下列任意一种，视为没写依据，必须补：

- 「我觉得」「一般来说」「大家都」「业内普遍」
- 「根据经验」但不说是谁的经验
- 「这样效果更好」但不说对谁更好、好在哪里
- 循环论证：「因为这样做更合适，所以选这个」
- 只写结论不写来源：「人群是 30 岁打工人」—— 从哪看出来的

## 合格的样子

```markdown
## D-003 · S1

**决策**：锁定"30 岁上下、被优化过、正在自责的打工人"，不要泛化的"职场人"
**依据**：
- 用户原话第 2 段出现 4 次"是不是我不行"，情绪指向自责，不是经济压力
- S0 记录的起因是简历被拒后反复修改，触发点具体到一个动作
- 这类人有一个共性是会主动搜索"被裁是不是我的问题"，搜索行为可预期
**反证条件**：如果目标平台的受众其实以 22–25 届应届生为主（他们是"还没被裁"而非"已被裁"），这条定位要改成"刚入职就赶上裁员"，整个 S2 需重做
**影响范围**：S2 全部五个方向、S4 的钩子语气、S6 的发布时间都建立在这条上
**时间**：2026-11-19 09:12
```

## 与闸门的关系

闸门问题必须能对着决策链问。如果用户想改某处，先定位到对应决策条目，看是哪条依据不成立——只改那一条，不要整段重来。

用户说"感觉不对"时，逐条念依据给他听，让他指出哪条不对。这比重新生成五个方向高效得多，也不会把已经对的部分一起冲掉。

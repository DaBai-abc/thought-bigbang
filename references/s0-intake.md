# S0 接入：把原料摊在桌上

## 目标

把用户脑子里那团模糊的东西，变成一份**可以往下加工的原料**。这一步不产出任何创意，只做记录和澄清。

## 五种起点，五种处理方式

先判断用户手里是什么。判断错了，后面全歪。

| 起点类型 | 识别信号 | 这一步的核心动作 | 主要风险 |
|---|---|---|---|
| 点子 | "我想做一期关于 XX 的" | 追问这个点子从哪来的，有没有具体触发点 | 点子往往是自己觉得有趣，别人无感 |
| 痛点 | 用户在抱怨某件事 | 挖到"疼的那个具体瞬间"，要场景不要概括 | 容易停在情绪层面，落不到可传播的内容 |
| 对话 | 用户复述了一段交流 | **原样保留对方的原话**，语气词都不要删 | 复述时被自动"书面化"，丢掉全部质感 |
| 信息差 | "很多人不知道 XX" | 核实这条信息是否真实、是否还新鲜、是否真的少人知 | 自以为的信息差可能是公开常识 |
| 成熟方案 | 用户已经想清楚了，讲得很完整 | 不重复推演，直接进入压缩和结构化的判断 | 想得越熟越容易自说自话，跳过人群验证 |

## 动作

1. **记录原话。** 用户怎么说的就怎么记，一个字都不要替它"整理通顺"。这些原话是后面文案的语言母本——一个创作者的辨识度全在这里。
2. **补两个缺口。** 无论哪种起点，S0 结束前必须知道两件事：这东西最初为什么让你想说；你希望看到它的人有什么反应。
3. **盘一次素材存量。** 手头已有什么：照片、数据、聊天记录、亲身经历、能约到的人、专业资质。这一步先不评判好坏，只登记。S3 会用到。
4. **不评判。** 不要在 S0 说"这个方向不错"或"这个可能没人看"。评判是 S2 和 S3 的事。S0 只负责把东西完整摊开。

## 必问（不超过 2 个）

- 这东西最早是怎么冒出来的？（要具体场景，不要"我一直想做"）
- 你希望看到的人看完之后，会有什么变化？（想法变了 / 去做一件事 / 只是觉得有意思）

能推断的不问。用户已经说得清楚的，直接填进产出文件，标注"（据你所述）"。

## 产出格式

写 `01-intake.md`：

```markdown
# S0 接入

## 起点类型
<点子 / 痛点 / 对话 / 信息差 / 成熟方案>

## 用户原话
> 原封不动摘录，保留口语、语气词、脏话也行

## 起因
<这东西最早从哪个具体场景冒出来的>

## 期望反应
<看完之后希望对方发生什么变化>

## 素材存量
| 类别 | 有什么 | 可用性初步判断 |
|---|---|---|
| 亲身经历 |  |  |
| 图片/视频 |  |  |
| 数据/资料 |  |  |
| 人脉/可约对象 |  |  |
| 专业资质 |  |  |

## 未解决
<还不清楚的，留给后面阶段>
```

## 收尾

按 SKILL.md 的闸门格式输出。S0 的闸门问题通常只有一个：确认起点类型判断对不对、原话记录准不准。

## 做好的标准

用户看到 `01-intake.md` 会说"对，就是这么回事"——而不是"大概吧"。如果对方的反应是后者，说明原话挖得不够，回去补。

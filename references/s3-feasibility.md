# S3 资源评估与收敛

## 目标

从五个方向里定下**一个能做完的**。注意定语：不是最好的，是能做完且不丢人的。

创作失败的主因很少是创意不够，多是方案超出了手上的资源，做到一半烂尾。

## 八个维度

逐项打分，每项 0 / 1 / 2。不要凭感觉，逐项问。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 出镜意愿 | 完全不想露脸露声 | 可以出声不出镜 | 愿意出镜 |
| 设备 | 只有手机、环境嘈杂 | 手机 + 安静空间 | 有相机/麦克风/灯 |
| 本周可投入时间 | 少于 2 小时 | 2–6 小时 | 6 小时以上 |
| 剪辑能力 | 完全不会 | 会用剪映基础功能 | 熟练，能做节奏和调色 |
| 预算 | 0 | 几十到几百 | 上千，可外包 |
| 素材存量 | 什么都没有 | 有零散图片/片段 | 有成体系的素材 |
| 专业支撑 | 这题只懂皮毛 | 有实际经验 | 是这行的从业者 |
| 持续能力 | 只打算做这一条 | 可能做几条 | 能做成系列 |

总分 0–16：

- **12 分以上**：可以做完整形态，实拍 + 剪辑 + 配音。
- **8–11 分**：单场景、单机位、口播或图文为主，靠文案质量取胜。
- **4–7 分**：做图文、海报或纯文字。不要碰需要多镜头的视频。
- **3 分以下**：先做一条纯文字发出去，验证有没有人看，别投入制作。

## 收敛的三条原则

1. **资源决定形态，不是喜好决定形态。** 用户想做精美的实拍但只有一部手机和一个吵闹的出租屋，就该改口播或图文。这不是降级，是选对战场。
2. **先能交出去，再谈做好。** 第一条内容的唯一任务是完成并发布。做到 70 分发布，比做到 95 分烂在草稿箱强。
3. **裁剪优先于放弃。** 方向选定了但资源不够，先裁方案：三分钟砍到六十秒、实拍换成图文、多镜头换成单镜头、系列拆成单条。裁到底还是做不了，才换方向。

## 裁剪手段清单

资源不足时按顺序尝试：

| 缺什么 | 裁法 |
|---|---|
| 出镜意愿 | 改口播 + B-roll，或纯图文 |
| 拍摄条件 | 换成一镜到底的固定机位，或纯素材剪辑 |
| 剪辑能力 | 用模板化剪辑，减少转场和特效，靠文案扛 |
| 时间 | 缩短时长，砍到只保留最核心的一个信息点 |
| 素材 | 用生成图或图表替代实拍 |
| 预算 | 去掉配乐版权支出，改用平台曲库 |

## 产出格式

写 `04-decision.md`：

```markdown
# S3 执行方案

## 资源评分
| 维度 | 分 | 说明 |
|---|---|---|
| 出镜意愿 |  |  |
| 设备 |  |  |
| 本周时间 |  |  |
| 剪辑能力 |  |  |
| 预算 |  |  |
| 素材存量 |  |  |
| 专业支撑 |  |  |
| 持续能力 |  |  |
| **合计** | **/16** |  |

## 判定的方案规模
<完整制作 / 轻量口播 / 图文海报 / 纯文字>

## 选定方向
方向 <N>：<标题>
选定理由：<和人群匹配 + 资源够用>

## 做过哪些裁剪
<原设想 → 裁剪后，逐条列>

## 这条内容的一句话定义
> 用 <形态>，对 <人群>，讲 <一个主张>，让他 <一个动作>。

## 明确不做
- <不做的方向>
- <不追求的效果>
- <不投入的成本>
```

最后一节"明确不做"是本阶段最重要的产出。没有它，后面每一步都会重新跑偏。

## 收尾

闸门问题 2–3 个：方案规模认不认、这条内容的一句话定义对不对、明确不做的这几条有没有异议。

## 做好的标准

用户看完会说"这个我能做"，并且知道从哪天开始动手。如果说"听起来不错但我可能没时间"，说明评分打虚了，回去重打时间项。

## 落链与面板

八项评分逐项落链，每项写清为什么是这个分。**时间项必须用过往行为校准，不用意愿校准**——用户说"这周能挤出十小时"，翻一下他上一条内容做了多久再打分。意愿和实际之间的差额，是所有烂尾的起点。

把评分同步进 `panel/data.json` 的 `score`，收敛结果写进 `decision`（选定方向、方案规模、做过哪些裁剪、明确不做），渲染面板让用户看到分数分布和判定结果。评分器只在对话里问不清楚时才用，用户能一句话答完就不必开面板。
